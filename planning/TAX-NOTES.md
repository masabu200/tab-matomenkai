# Pro 版（買い切り 300円）の税金と帳簿の扱い

作成: 2026-10-29。税理士には相談しない方針（利用者の判断）のため、一般的な制度の理解にもとづく運用メモ。確信度を各項目に付ける。制度改正や Stripe の仕様変更があれば見直す。

## 取引の形（前提）
- 購入者は Stripe の決済画面で支払う。Managed Payments（MoR）を使っているので、**購入者から見た販売者は Link, LLC（米国）**。購入者への領収書・返金・不審請求の対応も Link が行う。
- KWS は Link に商品を卸し、Link から**売上から税金と手数料を引いた額**が Stripe 残高に入り、KWS の銀行口座へ入金される。
- 日本国内の購入者でも Link が販売者になる（テストの決済画面で「消費税 10% お客様に代わって管理」と表示された）。

## 消費税（KWS は課税事業者・インボイス登録あり）
1. **Pro 版の売上は「不課税（国外取引）」として扱う。**（確信度：中）
   - KWS の取引相手は購入者ではなく Link, LLC（米国法人）。インターネットで提供するソフトウェアの利用権は「電気通信利用役務の提供」にあたり、提供する場所の判定は**受ける側の住所**（消費税法4条3項3号）。相手が米国法人なので国外取引＝不課税。
   - 不課税なので、消費税の申告では課税売上にも免税売上にも入れない（課税売上割合の分母にも入らない）。
   - 購入者に対する日本の消費税は、販売者である Link が扱う。KWS が購入者向けに適格請求書を出す必要はない（購入者には Link が領収書を出す）。
2. **Stripe の手数料（Managed Payments の手数料を含む）は、請求書の表示を見て区分する。**（確信度：中）
   - Stripe Payments Japan から日本の消費税込みで請求されていれば課税仕入れ、海外の Stripe から税なしで請求されていれば対象外。毎月の手数料の明細（Stripe の「請求書」または「手数料」レポート）で確認して、freee では見た通りの税区分で登録する。
3. 不安が残る点（確信度：低）：日本の購入者分を「KWS が国内で販売した」とみなされる可能性。Link が日本の消費税を代行しているなら二重にはならないが、もし Stripe のレポートで日本分の税額が 0 円のまま入金されているなら、その分は国内の課税売上（税込 300円＝税 27円）として申告する方が安全。年に1回、Stripe の Managed Payments の税レポートで日本分の扱いを確認する。

## 所得税（個人事業）
- 事業所得の売上。**入金額ではなく、販売額（Link から支払われる総額）を売上、手数料を経費**として両建てで記帳すると、後から照合しやすい。（確信度：高）
- 売上を立てる日は、Stripe の残高に入った日（Link からの支払いが確定した日）でよい。月ごとにまとめて1本の仕訳でも構わない。
- 全額返金した分は、返金した月の売上から引く（売上値引き・返品）。

## freee での記帳（毎月1回）
1. Stripe ダッシュボードの「残高 → 入金」で、その月の入金（または「レポート → 残高の概要」）を見る。
2. 仕訳の例（1件 300円・手数料が合計 30円だった月に 10件売れた場合）
   - 売上高 3,000円（税区分：対象外／不課税）
   - 支払手数料 300円（税区分：請求書の表示に合わせる。課税仕入れ 10% か対象外）
   - 普通預金への入金 2,700円（入金日）
3. 返金があった月は、売上高をマイナスで登録し、手数料が戻らない分はそのまま経費。
4. 証憑：Stripe の入金明細と手数料の請求書を PDF で保存（電子帳簿保存法）。

## 海外の税金
- EU の VAT、米国の売上税などは、Managed Payments（Link）が各国で計算・申告・納付する。KWS が各国で登録する必要はない。（確信度：高。Managed Payments の仕組みそのもの）

## 見直しのきっかけ
- Managed Payments の規約・手数料・対象国が変わったとき。
- 年間の Pro 版の売上が大きくなったとき（数十万円を超えたら、一度だけでも専門家に確認する価値がある）。
- 「特定プラットフォーム事業者」制度（令和7年4月〜、国外事業者が対象）の範囲が変わったとき。
